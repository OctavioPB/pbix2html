Power BI uses logical names (the ones you see here) that don't exist as such in Teradata. Give step 2's template a read-only SQL query for each one — a plain SELECT, same as you'd write for sql in the yaml itself — and the generated SQL will start from a FROM (<your query>) AS ... already built instead of an empty TODO. You'll still need to fill in columns and filters by hand (skill dax-to-teradata-sql).

⚠ Only a single SELECT (or WITH ... SELECT) statement is accepted — no INSERT/UPDATE/DELETE, no DDL, no stacked statements. This is a guardrail against a careless paste, not a security boundary: anyone entering a query here already has whatever access that query itself would use once it runs against Teradata.
